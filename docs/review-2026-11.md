## 2. P0：立即处理（服务端，可在半天内修完）

> **状态更新（12:20）**：工作区的并发补丁已针对本节三个 P0 改了代码，并用本节的 PoC 实测复测通过（详见附录 B）。下面保留 HEAD 的问题描述，便于 review 补丁与补回归测试。

### P0-1 单个畸形 URL 打死本地服务（未捕获 `URIError` → 进程退出）

- **位置**：`server/index.mjs:70`（`decodeURIComponent(pathname)`）；调用处 `server/index.mjs:354`（路由里 `return serveStatic(...)` 未包 try/catch）。
- **触发**（实测，仅一条只读请求）：
  ```bash
  curl.exe --path-as-is -s -o NUL -w "%{http_code}\n" http://127.0.0.1:8799/%
  ```
- **实测后果**：进程退出码 1，stderr：
  ```
  file:///.../server/index.mjs:70
    let rel = decodeURIComponent(pathname);
              ^
  URIError: URI malformed
      at decodeURIComponent (<anonymous>)
      at serveStatic (file:///.../server/index.mjs:70:13)
      at Server.<anonymous> (file:///.../server/index.mjs:354:10)
  ```
  `createServer(async (req,res) => …)` 里抛错 → unhandled rejection → Node 24 默认直接退出。课堂现场任何学生发一条 `/%` 或 `/%zz` 就结束演示（反复触发即 DoS）。
- **修法**：
  1. `serveStatic` 内 `let rel; try { rel = decodeURIComponent(pathname); } catch { return res.writeHead(400).end('bad request'); }`；
  2. 整个路由体包 `try { … } catch (e) { if (!res.headersSent) json(res, 500, {ok:false,error:'server_error'}); else res.end(); }`；
  3. 兜底 `process.on('unhandledRejection', e => console.error('[unhandled]', e))`（最后防线，不作为主要修复）。
- **回归测试**：`curl --path-as-is /%`、`/%zz`、`/%E0%A4%A` 三种均应 400 且 `/api/health` 仍 200。

### P0-2 静态文件黑名单可绕过 → 任意读（含 `.git/config` 与学生日志）

- **位置**：`server/index.mjs:69-86`：`rel = decodeURIComponent(pathname)`（:70）→ 黑名单正则（:73）→ `path.resolve(ROOT, '.' + rel)`（:76）→ `if (!target.startsWith(ROOT)) 403`（:77）。
- **根因**：
  - 黑名单 `/(^|\/)\./`、`/^\/(server|logs)\//`、`/\.env/i` 全部按 **`/` 分隔** 判断；
  - `%5c`（反斜杠）不会被 WHATWG URL 规范化为 `/`，但 **Windows 的 `path.resolve` 把 `\` 当路径分隔符**；
  - `:77` 的 `startsWith(ROOT)` 是**纯字符串前缀**，不校验分隔符边界 → 名字以 `taishigong-web` 开头的同级目录也能读。
- **实测（本机只读请求，均 200）**：
  | 请求 | 结果 |
  |---|---|
  | `/%5c..%5ctaishigong-webX%5ccanary.txt` | 200，读到 repo **之外**同级目录的文件（前缀绕过；为取证在 workspace 下临时建了同名前缀目录 + canary 文件，测完已删除） |
  | `/%5c..%5ctaishigong-webX%5c..%5ctaishigong-web%5cserver%5cindex.mjs` | 200，**15317 bytes**（绕过 `/server/` 403） |
  | `...%5c.git%5cconfig` | 200（`.git` 内容外泄） |
  | `...%5clogs%5cgenerate-2026-11-11.jsonl` | 200，**3140 bytes**（学生输入 + 生成正文的落盘日志） |
  | `...%5cserver%5c.env` | 403（仅因文件名含 `.env` 被正则挡住） |
- **后果**：只要服务在跑（尤其按 `.env.example` 建议改为 `TSG_HOST=0.0.0.0` 做多设备投屏时），同网段任何人可下载源码、git 配置、考据日志。`.env` 侥幸被拦，但**日志里的学生输入**是更实际的隐私风险。
- **修法**（替换 `:76-77`）：
  ```js
  if (rel.includes('\0') || rel.includes('\\')) return forbid(res);
  const target = path.resolve(ROOT, '.' + rel);
  const relPath = path.relative(ROOT, target);
  if (relPath.startsWith('..') || path.isAbsolute(relPath)) return forbid(res);
  let real; try { real = fs.realpathSync(target); } catch { return notFound(res); }
  const realRel = path.relative(fs.realpathSync(ROOT), real);
  if (realRel.startsWith('..') || path.isAbsolute(realRel)) return forbid(res);
  ```
  并把黑名单改到**规范化后的 `relPath` 分段**上判断（`/^(server|logs)(\/|$)/`、任一段以 `.` 开头）。
- **回归测试**：上面 5 条 + `%2e%2e`/`%5c`/大小写混写均 403；正常 `assets/bg/bg_court.jpg`、`js/data/scenes.p1.js` 仍 200。

### P0-3 `CORS:*` + 零鉴权 + 本机真实 Key + 全信任 payload

- **位置**：`server/index.mjs:45-50`（`Access-Control-Allow-Origin: CFG.allowOrigin`，OPTIONS 一律 204 放行）、`:35`（默认 `*`）、`.env.example:20`（把 `*` 写进模板）、`server/index.mjs:242-332`（`/api/generate*` 无任何鉴权/限流）；本机 `server/.env` **已存在真实 Key（35 字符，未入库、已正确 gitignore；本审查未读取/未回显其值）**。

  2. 若按 `.env.example:6-8` 的建议改成 `TSG_HOST=0.0.0.0`（课堂多设备），**同网段学生可直接调用**，甚至当免费 LLM 用；配合下面的注入面，输出不受控。

- **修法（性价比从高到低）**：
  1. 默认 `TSG_ALLOW_ORIGIN` 改为**空**（不回 ACAO，仅同源），需要跨源时显式列 origin + `Vary: Origin`；

  3. `nodeId` 白名单 `['L1','L3']`、`nextOptionId` 校验属于该节点选项；`sceneText` 改由服务端按 nodeId 提供（服务端目前**完全没有剧本数据**，需生成一份 `scene-meta.json` 或 require 数据，这是架构缺口）；
  4. 简单限流（IP+session：如 10 次/分钟、全局 60 次/分钟）+ 每日配额计数；
  5. 课后轮换 Key 若曾开放到局域网；`.env` 不要放共享盘/录屏范围。

## 3. P1：功能与逻辑缺陷（按对实测影响排序）

### P1-1 `selectableWhenFailing` 在 UI 层不生效 → 结局 13「廷尉堂」不可达

- **设计意图**：`js/engine.js:171-179` 明确"门槛失败但配置 `selectableWhenFailing` 才允许冒险"，失败则用 `failTerminal` 直接终局；`js/data/scenes.p1.js:184-204` 的 **L2A/B「当庭指斥酷吏」** 正是这样一条"凶多吉少"选项（`gate:{stat:'ming',min:55,selectableWhenFailing:true,failTerminal:{endingId:13,cause:'T2'}}`）。
- **实际实现**：`js/ui/screens.js:45` 只算 `ok = !gate || passGate(...)`；`:55` 对 `!ok` 直接输出 `disabled aria-disabled="true"`。于是 ming<55 时该按钮**永远点不动**；`:50-52` 的 `else if (o.gate.selectableWhenFailing)` 分支**永远不可达**（死代码）。键盘路径 `js/app.js:537` 同样只放行 `passGate`。
- **实测**（vm 内直接调用 `renderOptions(SCENES.L2A, {ming:15,…})`）：输出同时含 `disabled` 与"凶多吉少"，**不含** `opt-lock warn`。
- **后果**：`cause:'T2'` 的结局 13 变体「脊背是直的」（`js/data/endings.js:258-268`）在真实 UI 中**不可达**；玩家设计的"冒险一击"完全不存在。
- **修法**：`screens.js` 中把"可冒险"从 `locked` 里拆出来：
  ```js
  const risky = !ok && o.gate && o.gate.selectableWhenFailing;
  const cls = 'opt' + (!ok && !risky ? ' locked' : '');
  … (ok || risky) ? '' : ' disabled …'
  if (!ok) lock = '<span class="opt-lock' + (risky ? ' warn' : '') + '">' + esc(gateReason(o)) + '</span>';
  ```
  键盘处同样放宽；补一条测试：ming<55 时 L2A/B 可选且结算为结局 13/court。

### P1-2 A3「了此残生」的 `badIf` 阈值不可达 → 结局 13「只写了两页」永不出现

- **位置**：`js/data/scenes.p2.js:71-77`，`badIf: { stat:'jian', max:39, endingId:13, cause:'T3' }`。
- **交叉校验结论**（`design` 语义 BFS，40,279 状态）：到达 A3 时 **`jian` 的可达区间是 [45,100]**（`L3` 时最小 45：`P2/C −10`、`L1/A +5`、`L3/X1 +10`、`A1/C −10` 等组合后最低 45），**永远不会有 ≤39 的状态**；A3/C 在 `design` 下被选 16,233 次，全部按普通结局结算（`END`），从未触发 `ending:13`。
- **后果**：`T3 / variant 'silkworm'`（`js/engine.js:149-153`、`js/data/endings.js:269-278`）是**死内容**；「了此残生」实际按受刑线正常结算（多为结局 2「抑郁而终」），与选项文案"了此残生"的语义冲突。
- **修法**：把阈值改到可达区（≥45，若要保留一定的触发难度可取 `max:45` 并同步说明），或把该选项改为 `terminal:{endingId:13,cause:'T3'}`（明确是"自杀终局"），并同步 `endings.js` 的分档测试。
- **注意**：`badIf` 读的是**选择前**状态（`engine.js:181-187`），所以给选项加 `d.jian:-10` 不能解决此问题，必须改阈值。

### P1-3 自书匹配兜底 = 列表第一项 → 中性输入静默锁死最激进分支

- **位置**：`js/intent.js:46-62`：`var best = opts[0], bestScore = -1;`（:55）→ 遍历中 `s > bestScore` 才替换（:59）→ **所有选项分数都是 0 时返回 `opts[0]`**；`classify()` 无关键词命中时默认 `WRITE`（`js/intent.js:25`），而 `AFFINITY.L1.WRITE='A'`（:19）再 +12（:58）→ 直接锁定 A。
- **实测**：
  - `classify('站着不动')` → `{intent:'WRITE', confidence:0}`；`resolveOption(SCENES.L1, 50/50/50/50, '站着不动','WRITE')` → **`'A'`**（=出言辩护 → `route:'PUNISH'` 且带 `piece:7`）。
  - `resolveOption(SCENES.L3, 50/50/50/50, '问狱吏赎钱要几时纳齐','MERCY')` → **`'X1'`**（=接受宫刑！因为 MERCY 的亲和目标 X3 在 cai<80 时被过滤，`opts[0]` 兜底）。
- **后果**：玩家随手写一句中性描述，就被"自动"送上受刑线/宫刑；这与 UI 三处声明冲突：`js/ui/screens.js:88`、`:229`、`js/app.js:641` 均称"自书之笔不产出碎片、不计十二步"，但自书最终调用 `appChoose(既有选项)`（`js/app.js:404-411`），**会照常产出碎片、切换 route**。
- **修法**：
  1. 无命中（无 affinity、overlap 全 0）时**不推进**：返回 `null`，前端提示"此页只有这几条路可走"，让玩家点既有选项；

  3. 去掉 `WRITE` 的默认值与 L1 的 +12 权重（或让 tie 不取首项）。

### P1-6 "继续"重置自书次数与 `customCount` → 次数上限可无限绕过

- **位置**：`js/app.js:180-188`（`appResumeRun` 调 `appResetFree()`，`:155-168` 把 `freeLeft` 重置为 `cfg.freeLimit`、`customCount=0`）。
- **触发**：自书 3 次（`freeLimit:3`）→ Esc 回开始页 → "继续" → 次数回满；循环即无限自书。`customCount` 归零还会让排行榜上的"自书 N 次"标记消失（`js/ui/screens.js:313`）。

### P1-7 排行榜没有按"相似度"排序

- **位置**：`js/ui/screens.js:303-305`（`storeAllRuns(db).filter(...).slice(0,50)`）+ `:326`（文案"按人格相似度排序…越接近越前"）；而 `js/store.js:60-69` 的 `storeAllRuns` 只按 `at` **时间倒序**（:68）。

### P1-8 "只看正统局"过滤字段错误

### P1-11 无"清除本机记录"入口 + 坏存档无自救

- **位置**：`js/store.js` 全文无 `removeItem`/`clear`（grep 0 命中）；`js/store.js:18` 只校验 `version===1`。
- **触发 A（隐私）**：一台设备多人轮流玩（产品设计如此，`js/ui/screens.js:88`），上一位学生的 ID、局数、结局、图鉴、导出按钮全部留在下一位学生面前，无清空入口。

### P1-12 导入存档可注入 HTML/SVG（XSS）

- **位置**：`js/store.js:91-95` 只校验 `version/players`；`js/ui/screens.js:352`（个人面板雷达图）与 `:196`（结局雷达图）把 `stats`/`similarity` 直接拼进 SVG 字符串后写入 `innerHTML`（`TSG_Radar.buildSVG`，`js/ui/radar.js:85-163`）。

- **触发**：教师导入学生给的"存档"文件（课堂共享 U 盘/网盘）。
- **修法**：导入时逐字段白名单（`Number.isFinite` + `clamp(0,100)`；`endingId ∈ 1..13`；`pieces` 为整数数组）；`radar.js` 内对传入数值做 `Number()` 归一。
